Grounding Context

Codebase: Svenskt call center-intelligence (v0.5 beta): FastAPI + registry (~23 analyzers) + selektiv LLM deep path (Mistral/Groq) + Next.js webui. Hybrid local-first; INSIGHT-02 hoppar över thin heuristics när deep path körs. Profiler i configs/analyzer_profiles.yaml.

Learnings: Registry + graceful degradation är styrka. Quality report (2026-06-28): sentiment/intent ~4; emotion/role/enrichment ojämna (2–3); ~15 analyzers utan tester; saknad annoterad produktionskorpus (DATA-01). Strategi: lägg inte till fler thin heuristics utan motivering mot LLM.

External: Gong/Chorus/CallRail har flyttat till summaries + sentiment + CRM; gapet är aspect-level evidens, disagreement-hantering och outcome-kopplad eval. ABSA + LLM-as-judge är etablerad prior art.

Note: Tre generation-tier ideation-agenter + basis-verifier nådde API-gräns; pain/inversion/leverage fylldes av orchestrator; filtrering är orchestrator-only (degraded).

1. Aspekt-evidensplattform

pipeline-product Conf 88% Complexity Medium

Gör aspect-spans med obligatoriska citat till primär produktenhet (API, rapport, dashboard). Call-sentiment blir härledd aggregat. Local ABSA (aspect.py keyword triggers) är snabb sensor; LLM refined_aspects producerar “claim charts” per aspekt. Webui-kort och Fas4-sök utgår från aspekter, inte snittsentiment.

basis: direct: quality report local aspect=3 / LLM refined_aspects=5; src/llm/schemas.py AspectItem med evidence; ANALYZER_STRATEGY overlap “LLM preferred”. external: Gong topic/aspect intelligence; patent claim-chart practice.

rationale: Marknadsgapet och er starkaste LLM-output pekar samma håll — men rapportcentrum är fortfarande call-level sentiment.

downsides: Kräver UI/API-omläggning; keyword-ABSA false positives syns mer när aspekter är first-class.

2. Ärlig degradering — null före bluff

enrichment Conf 90% Complexity Low

När deep path är avstängd: returnera explicita null/unavailable för superseded-fält (empathy, trajectory, root_cause, coaching) istället för quality-2-heuristik. Amputera callcenter-default från ~18 analyzers till core local + deterministiska sensorer (CES, active_listening, negation). Dashboard visar “kräver deep path”.

basis: direct: ANALYZER_STRATEGY “Do not add new thin heuristik-analyzers”; quality report empathy/root_cause/upsell=2; deep_path redan skippar dem när LLM finns men ersätter med svaga heuristik när den saknas; callcenter default_selected ~18.

rationale: INSIGHT-02 halvfärdig — konsolidering när LLM finns, men “fake LLM” när den saknas underminerar förtroende.

downsides: Tommare offline-rapporter; sälj/edge måste omformulera värdeerbjudandet.

3. Kvalitets-OS — MQM + preferens-gate + riktig korpus

quality-eval Conf 85% Complexity High

Bygg ett sammanhållet kvalitetslager: (1) DATA-01 verklig annoterad korpus, (2) MQM-lik feltypologi (aspect/intent/emotion-fel med span+severity), (3) human preference som release-gate för deep path/coaching medan F1 behålls för core local. Fixtures styr inte längre LLM-produktbeslut.

basis: direct: ROADMAP High “Real corpus”; evaluate.py “Human preference study recommended”; analyzer_eval.yaml nästan enbart F1; ~15 analyzers utan tester. external: MQM/DQF error typology; PASTEL LLM-as-judge ABSA.

rationale: Utan detta optimerar ni mot syntetisk F1 medan Gong-gapet (evidens, coaching) förblir omätt — högst hävstång enligt egen assessment.

downsides: Kräver annoteringsbudget och processdisciplin; lång lead time innan payoff.

4. Override-provenance & kanaldiversitet

llm-deep Conf 78% Complexity Medium

Varje LLM-fält som ersätter local output måste bära override_provenance (vilken local signal, varför överskriden, evidence span). Policy: keyword-emotion och LLM-emotion får inte dela samma lexical failure mode utan diversitetskrav. Supersession loggas som auditerbar händelse.

basis: direct: deep_path LLM_SUPERSEDED set; emotion.py hybrid keyword+sentiment; INSIGHT-02. reasoned: samma lexical blinda fläck i emotion och ABSA-triggers. external: I&C diversity / defense-in-depth.

rationale: Produktifierar hybrid som förtroendearkitektur — säljbart till GDPR-känsliga call centers.

downsides: Schema- och prompt-komplexitet; mer loggvolym.

5. Styrd deep path — CCP + levande routing

pipeline-product Conf 75% Complexity Medium

Namngivna Critical Control Points före LLM (PII-clean, min segment quality, negation/sentiment sanity). Missad CCP → deep-output kasseras/eskaleras. Komplettera statisk YAML med runtime-val av analyzer-set från samtalsdrag (längd, intent-mix, risk). YAML blir priors.

basis: direct: should_use_any_llm redan segment/flag-gate; profiles.py statiska PROFILE_SPECS; cost/latency guards i Fas3. external: HACCP CCP; building FDD rule→deep diagnosis.

rationale: Gör LLM-spend till styrd process med corrective actions istället för feature-flag-spaghetti.

downsides: Risk för över-engineering; behöver tydliga CCP-trösklar och tester.

6. Streaming-first partial analysis

pipeline-product Conf 70% Complexity High

Vänd default: inkrementell segment-analys (WS) är huvudvägen; holistisk LLM är periodisk reconciliation vid hangup/var N sek. Tvingar fram vilka analyzers som överlever latensbudget; batch-zoo dör naturligt.

basis: direct: AGENT_CONTEXT real-time WS; assessment ~30–60s per demo-call; registry batch-topologisk. reasoned: latensconstraint kollapsar “fler analyzers”.

rationale: Exponerar verkligt produktvärde under live-coaching/supervisor-vy.

downsides: Stor arkitekturinsats; holistiska fält blir snapshots med race conditions.

7. Delad EvidenceSpan-kontrakt

core-local Conf 72% Complexity Low

Inför ett gemensamt EvidenceSpan (segment_id, start/end, quote, speaker) som obligatoriskt fält för sentiment-adjustments, emotion, aspect, compliance, llm_judge och LLM-overrides. En schema-version; UI renderar samma citatkomponent överallt.

basis: direct: aspect redan har evidence; trajectory evidence snippets; schema validation warn/strict; historiska fältnamns-buggar i quality report. reasoned: utan gemensam kontrakt kan aspect-plattform och provenance inte komponera.

rationale: Låg kostnad, hög compounding — möjliggör idé 1 och 4.

downsides: Migrering av befintliga analyzer-schemas; tillfällig warn-mode.
